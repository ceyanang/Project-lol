# Music Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play four looping, code-generated tracks (menu, map, battle, boss) that switch with the screen and react to combo and boss phase, with a saved on/off toggle.

**Architecture:** Pure data/logic (`src/music/scenes.ts` picks the track and layers from app state; `score.ts` turns a track into note events per bar; `scheduler.ts` schedules bars ahead of the audio clock) drives Web Audio voices (`voices.ts`) through one controller (`music.ts`) that owns the shared `AudioContext` bus, crossfades, ducking, mute and tab-visibility. `App.tsx` feeds it the scene.

**Tech Stack:** React 19, TypeScript, Web Audio API (existing `getAudioContext()` in `src/game/sfx.ts`), vitest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-22-music-design.md` (note data to port: `docs/superpowers/specs/music-reference/{synth,menu,map,battle,boss}.py`)

## Global Constraints

- No audio files; music is synthesized live with the existing shared `AudioContext` (`getAudioContext()`).
- Music starts on the first user gesture (tap or key); never before. Must not throw without Web Audio.
- Music sits well below sound effects: master music gain **0.12** against sfx **0.22**, and **ducks while a voice clip plays** so kana readings stay clear.
- Music pauses when the tab is hidden and resumes when visible (unless muted).
- Separate **music on/off toggle** on the title screen, saved in `profile.settings` (default **on**, including for old saves).
- Tunables in `src/config.ts`; `PLAN.md` documents the music. No new dependencies; tests, build and the deploy workflow keep working.
- Tempos: menu 54, map 112, battle 156, **boss 126** (the 92 bpm sample was too slow); boss phase change adds about 8% tempo.
- Reactive layers change on the next bar line, never mid-bar.

## Review Focus

1. Muted or toggled-off music never plays, and turning it back on resumes the current screen's track — Task 7 (smoke) and Task 8 (browser check).
2. Nothing starts before the first gesture, and a browser without Web Audio never throws — Task 7.
3. Rapid scene changes (title → map → fight in under a second) never stack tracks or leave old ones playing — Task 5 test, Task 7.
4. A layer change mid-bar never double-schedules or cuts notes already scheduled — Task 5 test.
5. A long hidden/suspended period never causes a burst of catch-up bars when the clock jumps forward — Task 5 test.

### Task 5: Look-ahead scheduler

**Files:** Create `src/music/scheduler.ts`; Test `src/music/scheduler.test.ts`.

**Interfaces:**
- Consumes: `Scene`, `Layers`, `notesForBar`, `barSeconds`.
- Produces: `interface SchedulerDeps { now(): number; play(ev: NoteEvent, when: number, secondsPerBeat: number): void; lookahead: number }` (times in audio-clock seconds); `class Scheduler { constructor(deps: SchedulerDeps); start(scene: Scene, layers: Layers, at?: number): void; setLayers(layers: Layers): void; tick(): void; stop(): void; readonly scene: Scene | null }`.
- Behaviour: `tick()` schedules every bar whose start is before `now() + lookahead`, calling `play(ev, barStart + ev.beat * spb, spb)` where `spb = barSeconds / 4`, and advances the bar index; `setLayers` only affects bars not yet scheduled; `start` while another scene is running discards the old scene entirely (no further events from it); if `now()` is more than one bar past the next bar start (a resumed tab), skip forward to the next bar line at or after `now()` instead of scheduling the missed bars.

- [ ] **Step 1: Write failing tests** with a fake clock and a `play` spy: first `tick()` schedules bar 0 at the `start` time with events at the right offsets; with `lookahead` 0.12 and 156 bpm, advancing the clock schedules exactly one new bar per bar duration (no duplicates across repeated `tick()` calls); `setLayers({hook:true})` after bar N is scheduled adds hook events from bar N+1 and none to bar N; `start('battle')` then `start('boss')` produces no `battle` events after the switch; `stop()` makes later `tick()` calls schedule nothing; jumping the clock forward by 60 s then `tick()` schedules at most two bars, none in the past; boss `enraged` bars are spaced by the shorter bar length.

### Task 6: Voices and reverb

**Files:** Create `src/music/voices.ts`.

**Interfaces:**
- Consumes: `NoteEvent`, `Voice`.
- Produces: `playEvent(ac: AudioContext, out: AudioNode, ev: NoteEvent, when: number, secondsPerBeat: number): void` (builds the nodes for one event, starts them at `when`, stops them after their tail so nothing leaks); `createReverb(ac: AudioContext, seconds: number): ConvolverNode` (generated noise impulse with exponential decay).
- Voice recipes (port the sample sounds from `music-reference/synth.py`): `pluck` = periodic wave of ~8 harmonics with `1/k` amplitudes, exponential decay, short noise click; `bell` = three inharmonic partials with long decay; `breath` = sine + octave with vibrato and filtered noise, slow attack; `pad` = detuned sawtooth pairs through a low-pass; `bass` triangle, `bassSq` square + sub saw; `arp` and `lead` = pulse waves (duty 0.25 / 0.125 via `PeriodicWave`); `horn` = detuned saws through a low-pass; `stab` = short saw cluster; `kick`/`taiko` = sine with pitch sweep (+ low noise for taiko); `snare`/`hat`/`openHat`/`tick` = shaped noise or short sine. Every voice multiplies by `ev.gain`.

### Task 7: Music controller and level meter

**Files:** Create `src/music/music.ts`; Test `src/music/music.test.ts`.

**Interfaces:**
- Consumes: `getAudioContext()` from `src/game/sfx.ts`, `Scheduler`, `playEvent`, `createReverb`, `TRACKS`, `CONFIG.music`.
- Produces: `startMusic(): void` (idempotent; call on the first user gesture; creates a master gain at `CONFIG.music.masterGain`, a reverb send and an analyser; starts a `setInterval` tick at `CONFIG.music.tickMs`); `setMusicScene(scene: Scene | null): void` (crossfades over `CONFIG.music.crossfadeMs` using one gain bus per scene run; `null` fades out and goes silent; same scene again is a no-op, so screens sharing a track do not restart); `setMusicLayers(layers: Layers): void`; `setMusicEnabled(on: boolean): void` (off fades out and stops ticking; on resumes the last requested scene); `duckMusic(seconds: number): void` (ramps the master to `masterGain * CONFIG.music.duckGain` over `duckFadeMs`, back after `seconds`); `musicLevel(): number` (analyser RMS in `[0, 1]`, `-1` when not started). A `visibilitychange` listener suspends the context when hidden and resumes it when visible (only if enabled and started).
- Requests made before `startMusic()` (scene, layers, enabled) are remembered and applied when it starts.
